# Decisions log

Append newest at the bottom. Format: date — decision — why. Don't re-decide something listed here
without the owner. In a new project, start a fresh log (skill `new-project-from-boilerplate`).

- 2026-11-08 — Copy-and-own starter, not a library: no forks, no published packages, everything readable, every optional module deletable as one folder. — The owner renames and rewrites freely; nothing to keep in sync.
- 2026-11-08 — pnpm + Turborepo monorepo, scope `@app/*` (find/replace to rename). — One app today, room for more apps sharing `ui`, `db` and `core`.
- 2026-11-08 — All business logic is `defineAction` in `packages/core`; UI, REST and MCP are generated from the registry; `apps/web` never touches the database. — One rule set for UI, API and AI; self-documenting.
- 2026-11-08 — No `next-safe-action`. A form is `<ActionForm action="area.verb">` over a single `invokeAction` server action. — One mechanism instead of two; a new screen is one action plus one form; errors and refs behave the same everywhere.
- 2026-11-08 — Data only through Drizzle over `DATABASE_URL`; never Supabase JS, the Neon Data API or PostgREST for data. — Authorization lives in actions; the code is identical on Neon and Supabase.
- 2026-11-08 — Dual backend selected by `BACKEND=neon|supabase`; only auth and file storage differ, each behind a small interface. `auth_user_id` is TEXT. — Provider is a one-afternoon choice; removing one is deleting an adapter and an env block.
- 2026-11-08 — Our tables in schema `app`, RLS on, no grants to `anon`/`authenticated`. — A leaked browser key reaches nothing.
- 2026-11-08 — One contacts table for every person; tags describe, roles grant; permissions are defined in code, roles stored in the DB. — Staff can be customers; access changes are deliberate and audited; permission changes are reviewed in PRs.
- 2026-11-08 — Activity log + field-level change log via a Postgres trigger on every `app` table, linked by `activity_id`. — Catches every write, including ones outside the app; no per-action diff code to forget.
- 2026-11-08 — Errors get a per-occurrence reference (`E-…`) + diagnosis code + fingerprint, stored in `app.error_events`, with an "AI brief" and a `fix-error` skill. — A static code names a category, not a cause; the reference lets an AI fetch the full context.
- 2026-11-08 — Rules in AGENTS.md are enforced mechanically by `scripts/check-rules.mjs` (configurable via its `CONFIG`). — A failing check is followed every time; written rules only most of the time.
- 2026-11-08 — One brand ramp (`--brand-50..900`) with `--primary` = brand-500; neutral indigo default; dark mode lightens surfaces rather than inverting. — Rebranding is one token change.
- 2026-11-08 — Phosphor icons only, via `@app/ui/components/icons`. — One icon set, one place to add one, checked by `icons-from-ui-only`.
- 2026-11-08 — Dates are stored UTC and formatted in `APP_TIME_ZONE` (default `America/Chicago`) through `@app/ui/lib/dates`. — Servers run in UTC; evening times must not show as the next day.
- 2026-11-08 — Money is always integer cents. — No floating-point rounding bugs.
- 2026-11-09 — Lint is oxlint (one root `.oxlintrc.json`) plus `tsc`, not ESLint. — Fast, one config, covers React hooks, jsx-a11y, Next and import rules; knip covers dead code (exports are intentionally not checked: core's exports are its API).
- 2026-11-09 — The e2e suite runs `next dev` with `DEV_LOGIN`, against a database it drops and recreates every run (`<name>_e2e`). — Dev login is refused by production builds on purpose; a fresh database means a failed run cannot poison the next.
- 2026-11-09 — Dev-only crash routes live in `apps/web/app/api/dev/` and 404 unless `DEV_LOGIN` is on outside production. — The error pipeline needs real crashes to be tested end to end.
- 2026-11-09 — Open axe violations are listed per page in `e2e/a11y.spec.ts` (`KNOWN`) with a TODO item; the list may only shrink. — Zero serious/critical is the bar, but existing debt must not hide new regressions. (2026-11-09, later: the list reached zero and is empty; keep it that way.)
- 2026-11-09 — Auth adapters turn a provider 4xx into a message and anything else into a thrown, reported error; Supabase sign-out is `local` scope. — An outage must not read as "wrong code", and signing out of a laptop must not sign out the phone.
- 2026-11-09 — Migrations run from the Vercel build command and are expand-then-contract. — A failing migration fails the build and the old deployment keeps serving; backwards-compatible schema makes code rollback safe.
- 2026-11-09 — `scripts/new-project.mjs` removes `automations` (events + automations), `docs` and `brand`; notifications, jobs and REST/MCP are removed by hand. — Those three separate by deleting folders and registrations; the rest are coupled to actors, auth and the delivery log.
- 2026-11-09 — The server shows dates in the signed-in person's `tz` cookie zone through `getServerDates()`; the business rules (quiet hours, "daily at 8:30") keep using `APP_TIME_ZONE`. — A display preference must not change when a message is sent; the page and the shell must agree on what time it is.
- 2026-11-09 — UI components that speak take a `labels` prop with English defaults; the web app passes translated labels from `lib/ui-labels.ts`. — `packages/ui` stays free of an i18n library, and a copy of it needs no translation setup.
- 2026-11-09 — The email-link routes redirect (303) a person's click to `/newsletter/confirmed` / `/newsletter/unsubscribed`; the one-click `List-Unsubscribe=One-Click` POST (RFC 8058) gets JSON, not a redirect. — People land on a page that looks like the site; mail apps get the plain answer they expect.
- 2026-11-09 — File uploads are tested end to end against `scripts/dev-s3.mjs`, an in-memory S3 stand-in started by the Playwright config; it never checks signatures. — No bucket or credentials are needed to prove the browser → storage → link path, and the same script serves local development.
- 2026-11-09 — A data export's signed link carries `response-content-disposition: attachment`. — The `download` attribute of a link is ignored cross-origin, so without it the browser would open the JSON instead of saving it.
- 2026-11-09 — Bulk and history reads exist as actions (`errors.resolveMany`, `errors.occurrences`, `system.cronRuns`, `activity.list` `from`/`to`, `notifications.typeDefaults`, `notifications.preferencesFor`), and screens use them rather than approximating from other lists. — A screen that guesses from a capped list shows wrong numbers; the same actions serve REST and AI.
